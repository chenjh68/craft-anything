# 变更记录

本文件记录 `board-extract` 的可用版本。版本号只在这个目录内有效，与 `game_dev` 整体无关。

## 2.5.0 — 2026-11-21

陌生游戏的接入：`probe`，一张图进去、一份配置出来。

**新增**

- `probe` 子命令：把画面里最像“牌面”的颜色找出来，配它被压暗的形态，量出一张牌多大，
  顺带给背景色与尺寸阈值（`--out config.json` 可直接喂回 `--config`）
- 判据不是“颜色出现得多”，而是：格子**内部**确实是这个颜色、匹配到的必须是**亮面**（不是阴影）、
  一张牌的面积占画面 0.3%–12%
- 可玩页的背景色、牌面/暗面颜色改为由配置驱动（原来写死为羊了个羊的浅绿）

**实测（MuMu 上的 Shattered Pixel Dungeon 选英雄界面）**

- 整屏 `check`：0.0% 覆盖率 + 取色提示
- `probe --crop`：自动给出 `face 40,40,40 / dim 32,32,32 / tile 186x156 / background 0,0,0`
- `run`：6 张英雄卡全部检出（另在裁剪边缘多出 1 个误检），0 误放行、1 误挡；复刻页与原图同底色

## 2.4.2 — 2026-11-21

真机（MuMu 模拟器）实测后修的三处。

**修复**

- `capture` 报的尺寸是 `wm size`（设备竖屏 1440×2560），而横屏游戏的截图是 2560×1440。
  现在从 PNG 的 IHDR 读真实尺寸，并在两者不同时标注设备尺寸
- 找 adb 时先命中了 scrcpy 自带的副本，它和 platform-tools 抢同一个 server 端口，`devices` 会交替返回空。
  改为 platform-tools 优先、scrcpy 仅作兜底
- adb server 刚重启时第一次 `devices` 会返回空：`capture` 现在先 `start-server`，空结果再重试一次

**实测记录**

- MuMu（Android 15，1440×2560）取图正常，3.0 MB / 2560×1440
- 用开源的 Shattered Pixel Dungeon 验证：整屏 `check` 给 0.0% 覆盖率提示；按 `palette` 取
  `face = 160,160,144`、`dim = 96,96,86` 后，选英雄界面的 6 个格子全部检出（6/6 可点、0 误判）

## 2.4.1 — 2026-11-21

- 修：`--crop` 之后页面缩放仍按配置里的 1330 算，手机裁出的 665 宽会把整盘画成半尺寸。
  现在裁剪时 `boardWidth` 默认取裁剪宽度；配置文件里显式写了仍以配置为准
- 补回归测试：裁剪后的页面必须按裁剪宽度缩放（`test/smoke.test.mjs`）
- 用 1080×1920 的合成手机整屏验证：`check` 先给「约 64x66」提示，加 `--tile` 后 38 张 / 19 可点 /
  0 误判；自动命名 38/38——模板库在全尺寸学到的签名在 1/2 缩放下仍然可用

## 2.4.0 — 2026-11-21

换游戏或换设备时的配色诊断。

**新增**

- `check` 多输出一块 `palette`：图片里占比最高的 5 种颜色及像素数，以及配置的 face / dim 各覆盖多少像素
- 覆盖率低于 2% 时给 `colours` 提示，直接说明该去哪里取色：
  「only 0.1% of pixels match face 1,2,3 / dim 4,5,6; pick a value from palette.top and put it in the config」
- `test/palette.test.mjs`：正确配色覆盖 14%（face 160k + dim 110k 像素），错配只有 0.1%

## 2.3.0 — 2026-11-21

不同分辨率的截图。

**新增**

- `--tile WxH`：说明这张图里一张牌面多大，尺寸阈值按比例跟着走
- 识别自检：牌面尺寸与配置相差 20% 以上，或只认出零星几张时，`check` / `run` 会给出
  「这里的牌面约 64x66 — 请用 --tile 64x66」。把参考截图缩到 1/2、1/3、1/4 实测：
  默认阈值只认出 28 / 1 / 0 张，照提示重跑三种都是 38 张、19 可点
- `test/scale.test.mjs`：把这条性质固定下来（先给提示、照提示能全找到）

**改变**

- `minSide` / `minArea` 不再写死，默认由 `tile` 推导（128×130 → 40 / 1200，与原标定值一致）；
  配置文件显式写了仍以文件为准

## 2.2.0 — 2026-11-21

安卓链路在没有真机的情况下也能验证。

**新增**

- `--crop x,y,w,h`（`run` / `check`）：手机整屏截图先裁出棋盘。裁剪区就是落盘的 `shot.png`，
  `level.json` 的坐标全部相对它，`run.json` 记录该矩形；越界直接报错，不静默截断
- `test/capture.test.mjs`：用假 adb 跑通「列设备 → screencap → pull → PNG 魔数校验 → detect」全链，
  并覆盖无设备、设备未授权、指定序列号不存在、传输损坏四种失败
- `capture` 的 `run` 参数可注入（供测试），失败信息区分「没有设备 / 设备未授权 / 序列号不存在」
- 文档补模拟器接法（BlueStacks/雷电 5555、MuMu 7555、夜神 62001）与裁剪用法

**改变**

- 用户级错误只打印一行原因，堆栈要 `DEBUG=1` 才显示

## 2.1.0 — 2026-11-21

手机端入口与竖屏适配。

**新增**

- `capture` 子命令：从安卓手机取图（`adb screencap` 写设备再 `pull`，避开 Windows 下
  `exec-out` 的换行损坏）。自动在 PATH / WinGet / Android SDK 里找 adb，只连一台设备时自动选中，打印屏幕分辨率
- 可玩页按手机重做：画布保持逻辑坐标（720 宽）、按视口宽度等比缩放，按 `devicePixelRatio` 渲染保证清晰
- 触摸：`pointerdown` + `touch-action: none`，不会触发页面滚动或双击缩放；屏幕上有「撤回」按钮，与 `Z` 等价
- `window.__board` 只读句柄（`size` / `state` / `clickable` / `tray`），给自动化测试用
- `test/page.test.mjs`：真实 Chrome 里以 390×844 触摸视口验「装得下、托盘不出界、点得动、撤得回」，无浏览器时跳过

**修复**

- 槽位托盘总宽 732 px 超出 720 画布，左右被裁——改为按可用宽度反算每格尺寸
- 「剩余」把进了槽位的牌也算在桌面上，点牌后数字不动
- 页面高度按棋盘实际高度算，不再固定 1010

## 2.0.0 — 2026-11-21

包化重构：从"一组脚本"变成可复用的包。

**新增**

- 单一入口 `bin/board-extract.mjs`，六个子命令：`run` / `check` / `learn` / `eval` / `slots` / `init`
- `src/config.mjs`：默认参数 + 逐游戏配置校验。换配色不同的同类游戏只写一份 `board-extract.config.json`
- `src/invariants.mjs`：把"可点集合必须等于截图亮面"变成可断言的不变量，写进 `run.json` 与 `run.md`
- `npm run ci`：4 个冒烟测试 + 真实截图跑全链 + 不变量断言，任一项破就红
- `.github/workflows/board-extract.yml`：同样的门禁，仅 `tools/board-extract/**` 变更时触发
- `exports` 双入口，可从其他项目 `import { runPipeline }`

**改变**

- 目录重排：脚本进 `src/`，模板进 `assets/`，模板库留在 `library/`（项目数据，不入发布包）
- 报告新增两行体检指标：层级判定覆盖率、可点一致性

**验证**

- 同一张真实截图，重构前后 `tiles` / `piles` / `counts_visible` 完全一致
- 留一法 29/38（完整可见的 28 张里 27 张，误配 0）
- 层级 25/28 对由描边判定，24 与明暗一致；可点集合 38/38

## 1.x — 2026-11-21 之前

脚本阶段，未单独发版。`detect.js` → `build-level.js` → `make-playable.js` → `compare.mjs` 依次手工调用，参数靠命令行位置传递。

关键结论在这一阶段得出：

- 牌面 128×130 px，亮面 `(240,248,200)`、被压面 ×0.6
- 真实叠压只重叠 12–14 px，判定"挡住"的门槛必须低到 5%，否则暗牌被误判可点
- 图标区分靠 RGB 而非灰度（绿色蔬菜 vs 橙色胡萝卜在灰度上过近）
