# 游戏研发流程 · 关卡复刻流水线

- 编写日期：2026-11-21
- 适用范围：**所有"照着已有游戏做自己版本"的场景**，不绑定具体游戏
- 配套：[`美术与素材管线.md`](美术与素材管线.md)（素材怎么来）、[`多端架构设计.md`](多端架构设计.md)（怎么发布）
- 工具：`tools/board-extract/`（Node 18+，运行时只依赖 `pngjs`；截屏/对比可选依赖本机 Chrome + `playwright-core`）。命令入口 `bin/board-extract.mjs`，含 `run/check/learn/eval/slots/init` 与冒烟测试 `npm test`

---

## 0. 这份流程要防的三个坑

| 坑 | 后果 | 解法 |
|---|---|---|
| **每关手工码关卡** | 一款游戏 30 关 = 30 次手工摆牌，批量无从谈起 | 截图即模型：坐标、层级、牌型从像素里来 |
| **复刻完不知道像不像** | 凭感觉调，越调越偏 | 复刻页自动截图 + 与原画面并排，差异可看可存 |
| **换一款游戏就从零开始** | 工具绑死在一款游戏上 | 图标模板库：命名一次，后续关卡自动认 |

三条原则：

1. **观测与推断分开记录**：模型里每张牌都标明"看到什么"和"推出来什么"，错了能回溯
2. **人工只做机器做不了的两件事**：截图、复核图标聚类
3. **每次运行留痕**：`run.json` 记录输入、参数、耗时、产物，同一关卡可重跑复现

## 1. 五段流水线

| 段 | 输入 | 工具 | 输出 | 人工动作 |
|---|---|---|---|---|
| ① 捕获 | 游戏画面 | `board-extract capture`（安卓走 adb）或任意截图工具 | `shot.png` | **要人**：把游戏拉到能看全棋盘的状态 |
| ② 识别 | `shot.png` | `src/detect.mjs`（`check` / `run`） | `detect/tiles.json`（坐标/尺寸/明暗/签名）、`detect/montage.png`（聚类代表图） | 无 |
| ③ 命名 | `tiles.json` + 模板库 | `src/library.mjs`（模板库自动匹配） | `types.auto.json`（含置信度） | **要人**：只看未命中的牌 |
| ④ 建模 | `tiles.json` + `types.json` | `src/build.mjs` | `level.json`、`overlay.png`（绿=可点/橙=被压） | 抽查 `overlay.png` |
| ⑤ 复刻+比对 | `level.json` | `src/playable.mjs`、`src/shot.mjs`、`src/compose.mjs` | `playable/index.html`、`clone.png`、`compare.png` | 看对比图判断是否要回改 |

一条命令跑完 ②–⑤：

```bash
node tools/board-extract/bin/board-extract.mjs run \
  --shot refs/yang_sheep/board_20261121.png \
  --out refs/yang_sheep/2026-11-21 \
  --game "羊了个羊：星球" --level "每日关卡 · 11月21日" \
  --piles refs/yang_sheep/piles_20261121.json \
  --types refs/yang_sheep/types_20261121.json \
  --library tools/board-extract/library
```

`--piles`（侧视堆）和 `--types`（人工命名）都可省略；省略 `--types` 就完全靠模板库自动命名。

**从安卓手机直接取图**（不需要先导到电脑）：

```bash
node tools/board-extract/bin/board-extract.mjs capture --out shots/phone.png
node tools/board-extract/bin/board-extract.mjs run --shot shots/phone.png --out refs/<game>/<date>
```

`capture` 依次在 PATH、WinGet 安装目录、Android SDK 里找 adb，只连一台设备时自动选中，并顺手打印屏幕分辨率。它把图写在设备上再 `pull` 回来——Windows 下 `adb exec-out screencap` 会被换行转换弄坏 PNG。
配合 `scrcpy` 可以把手机画面投到桌面，`adb shell input tap x y` 用来在手机上复现操作，两者都不改变原游戏。

**模拟器同样适用**：Android Studio 的 AVD 直接出现在 `adb devices`；第三方模拟器走 TCP，先连一次即可，只有端口不同（各家常见默认值，以模拟器设置里显示的为准）：

| 模拟器 | 命令 |
|---|---|
| BlueStacks / 雷电 | `adb connect 127.0.0.1:5555` |
| MuMu | `adb connect 127.0.0.1:7555`（新版 16384） |
| 夜神 | `adb connect 127.0.0.1:62001` |

建议把模拟器设成竖屏手机型号（1080×1920 或 720×1280）并全屏跑游戏，截出来的图才接近真机形态。

**整屏不等于棋盘**：手机截图里还有标题栏、槽位、按钮和系统 UI，`detect` 会把能认出的牌面都算进去。用 `--crop` 只把棋盘交给它：

```bash
node tools/board-extract/bin/board-extract.mjs check --shot shots/phone.png --crop 0,320,1080,1200
node tools/board-extract/bin/board-extract.mjs run   --shot shots/phone.png --crop 0,320,1080,1200 --out refs/<game>/<date>
```

裁剪区就是落盘的 `shot.png`，`level.json` 的坐标全部相对它；`run.json` 里记为 `crop`。越界的裁剪会直接报错，不做静默截断。裁剪同时决定可玩页的缩放基准（`boardWidth` 取裁剪宽度），配置文件里显式写了 `boardWidth` 则仍以配置为准。

**分辨率不同，牌面也变小**：尺寸阈值是「一张牌面的比例」，所以换分辨率要告诉它这张图里一张牌多大：

```bash
node tools/board-extract/bin/board-extract.mjs check --shot shots/phone.png --tile 36x37
```

不用猜。认出的牌面与配置对不上（或只认出零星几张）时，它会直接说看到多大：

```
hint: the faces here look different: about 64x66 against tile 128x130 — pass --tile 64x66
```

照提示重跑就能拿回整盘：参考截图缩到 1/2、1/3、1/4，默认阈值分别只认出 28、1、0 张，
加了 `--tile` 三种都是 38 张、19 可点（`test/scale.test.mjs` 固定了这条性质）。

**配色对不上也会先说清楚**：`check` 打印的 `palette` 里有占比最高的 5 种颜色和像素数，以及配置的 face / dim 各覆盖多少。覆盖率低于 2% 时它直接给出结论，而不是丢一句「0 张牌」：

```
"colours": "only 0.1% of pixels match face 1,2,3 / dim 4,5,6; pick a value from palette.top and put it in the config"
```

换游戏的做法：从 `palette.top` 取一个值当 `face`，把它乘 0.6 当 `dim`，写进截图旁边的 `board-extract.config.json`（`board-extract init` 会生成一份起点）。

**陌生游戏可以直接让工具提配置**（不用肉眼找色）：

```bash
node tools/board-extract/bin/board-extract.mjs probe --shot shots/hero.png --crop 110,320,660,400 --out config.json
node tools/board-extract/bin/board-extract.mjs run   --shot shots/hero.png --crop 110,320,660,400 --config config.json --out runs/x
```

`probe` 的判据是：格子**内部**确实是这个颜色、匹配到的必须是**亮面**（阴影会让 z 序反过来）、一张牌占画面 0.3%–12%。它还会一起给出背景色与尺寸阈值，`--out` 出来的文件可以直接被 `--config` 吃。**提完必须看 `overlay.png`**——那是唯一能发现“看起来合理但框错了”的环节。

**没有真机也能验这一段**：`test/capture.test.mjs` 用一个假 adb 跑通「列设备 → screencap → pull → 校验 PNG 魔数 → 交给 detect」全链，并覆盖无设备、未授权、指定序列号不存在、传输损坏四种失败。

**竖屏与触摸**：可玩页的画布保持自己的逻辑坐标（720 宽），按视口宽度等比缩放，所以同一份 `level.json` 在手机和桌面都能看；托盘按可用宽度反算每格尺寸，不会被裁；点击走 `pointerdown` 且 `touch-action: none`，不会触发页面滚动或双击缩放；`Z` 与屏幕上的「撤回」按钮等价。

## 2. 层级怎么定（谁压谁）

截图只能直接给出"亮/暗"两种状态，但复刻页需要知道**具体谁压着谁**，否则点掉一张牌后下面那张会不会露出来就是猜的。

做法：牌有 2px 深绿描边，被压住的部分描边会断。对每一对有实质重叠的牌，沿其中一张的边框在另一张的矩形内采样，看描边还在不在——**在 = 这张在上面**。

实测（同一次运行）：

| 指标 | 数值 |
|---|---|
| 有实质重叠的牌对 | 28 |
| 能用描边判定 | 25 |
| 与"亮/暗"一致 | 24 / 25 |
| **按层级算出的"可点集合" vs 截图亮面** | **38 / 38 完全一致** |

最后一行是这条流水线的验收线：层级推错了，可点集合立刻对不上。若哪天这个数掉下来，说明遮挡判定或整牌还原出了问题。

> 一个反直觉的细节：真实叠压只重叠 **12–14px（约一张牌的 10%）**，最初我把"挡住"的门槛设成 45% 面积，结果 15 张暗牌被当成可点。门槛必须按"只要接触即算压住"来设（5%）。

## 3. 自动命名：模板库怎么工作、实测多准

- 每张牌的签名 = 内侧 70% 区域的 **12×12 RGB**，被压住的牌先按亮度 ×1/0.6 还原
- 匹配 = 与模板库同型签名的平均 RGB 距离；超过 36 判为"未命中"，不猜
- 第一次跑完，用 `learn` 把人工确认过的牌写进模板库：

```bash
node tools/board-extract/bin/board-extract.mjs learn \
  --tiles <run>/detect/tiles.json --types <run>/types.json \
  --library tools/board-extract/library
```

**实测（2026-11-21，羊了个羊每日关卡，38 张可见牌，留一法）**

| 范围 | 命中 | 误配 | 未命中 |
|---|---|---|---|
| 全部 38 张 | 29（76%） | **0** | 9 |
| 完整可见的 28 张 | 27（96%） | **0** | 1 |

两条结论：

1. **未命中的 9 张全是"只露出一角"的牌**——它们的签名本来就不完整，交给人看一张聚类图即可
2. 过程中出现过 3 处"工具与人工不一致"，复核后发现 **2 处是人工标注错了**（把白菜标成红桶、把干草标成篝火），工具是对的。所以流程里保留"自动命名 + 抽查"，而不是"人工全标"或者"全自动照单全收"

## 4. 批量：一款游戏多关 / 多款游戏

目录约定（一次运行一个文件夹，永不覆盖）：

```
refs/<游戏 slug>/<日期>/
  shot.png  detect/  types.auto.json  types.json
  level.json  overlay.png  playable/index.html
  clone.png  compare.png  run.json  run.md
```

多关批量就是一次循环，`--date` 换成关卡日期或序号：

```bash
for d in 2026-11-21 2026-11-22 2026-11-23; do
  node tools/board-extract/bin/board-extract.mjs run --shot "shots/$d.png" \
    --out "refs/yang_sheep/$d" \
    --game "羊了个羊：星球" --level "$d" \
    --library tools/board-extract/library
done
```

多款游戏同理，换 `--slug` 与 `--game`；**模板库是跨游戏共用的按牌型分文件**，同名牌型会互相增强，异名不会互相污染。

工具本身的回归门禁：`cd tools/board-extract && npm run ci`（4 个冒烟测试 + 真实截图跑全链 + 可点一致性必须为 0 误判）。改识别/还原/层级后先过这道门。

批量验收（每关必过）：

1. `run.md` 里"自动命名命中"是否 ≥ 70%；低于这个数说明截图质量或牌型集变了
2. `overlay.png` 是否每张牌都有框、没有框到草地
3. `compare.png` 两边集群位置是否能一一对上
4. `level.json` 的 `counts_visible` 里是否有明显不可能的分布（例如某型只有 1 张且无侧堆解释）

## 5. 与主流程的接口

| 场景 | 接法 |
|---|---|
| 复刻页要变成正式原型 | 把 `playable/index.html` 的逻辑搬进 `prototypes/<name>/`（Vite 工程），关卡数据直接用 `level.json` |
| 素材要不要用原游戏的 | **不用**。复刻页用 emoji 替身是刻意的；正式版按 [`美术与素材管线.md`](美术与素材管线.md) 走自产或授权素材 |
| 数值从哪来 | 牌型、层数、槽位数来自模型；计分、道具次数等规则仍靠人工确认，模型不提供 |
| 每日关卡只能玩一局 | 截图要在开局的静止状态拍；一旦落子，槽位状态会污染棋盘识别 |

## 6. 已知边界（别当成 bug）

- **加密包读不了**：PC 微信把 `.wxapkg` 存成 `V1MMWX`，工具只报告加密、不解密；可读入口是运行时缓存（`usr/gamecaches`，Cocos bundle）与截图
- **侧视堆内容未知**：只能数出条纹数量（本例 11 和 9），里面是什么牌看不出来
- **层级大部分是测出来的**：25/28 对有描边证据，其余按"亮压暗"兜底；可点集合与截图一致（38/38），但两牌重叠且都亮或都暗时，上下是任意的
- **完整矩形是还原的**：被压住的牌只露出局部，模型按"钻在邻居下面"的规则补全，可能偏一格
- **图标是替身**：emoji，不是原美术

## 6.5 真实运行案例：羊了个羊（2026-11-21）

`refs/yang_sheep/2026-11-21/`，配置"羊了个羊 PC"，`board-extract v2.0.0`。

### 数据

| 项 | 值 |
|---|---|
| 检出牌数 | 38（可见） |
| 可点牌 | 19（占 50%） |
| 侧堆 | 2 个：10 层 + 面 / 8 层 + 面 |
| 层级判定 | 25/28 对由描边判定，24 与明暗一致 |
| 自动命名 | **38/38 命中，平均置信度 0.98**，人工覆盖 0 |
| 类型数 | 12 种（hay 6、yarn 4、cabbage 4、leaves 4…） |
| 牌面尺寸 | 129 × 130 px，位置是**任意像素偏移**，不是网格 |
| 画布 | 原图 1330×1450 → 复刻 720×1010（scale 0.541） |

### 耗时

| 阶段 | 耗时 | 说明 |
|---|---|---|
| detect | **210 ms** | 检测很快 |
| build | **379 ms** | 建模也快 |
| playable | **15 ms** | 生成可玩页几乎不耗时 |
| screenshot | **4453 ms** | ⚠️ **瓶颈在这里** |

> 结论：**计算不是瓶颈，截图是。** 想批量跑多关，优先优化截图环节（复用浏览器实例、跳过重复截图）。

### 复刻到什么程度（重要）

把 `compare.png` 左右一对比就能看出：

| 维度 | 还原度 |
|---|---|
| 牌的位置、尺寸、层级、z 序 | ✅ 完全一致 |
| 牌型（38 张全部命名） | ✅ 完全一致 |
| 侧堆层数 | ✅ 数得准（10 / 8） |
| **图标美术** | ❌ **emoji 替身**（🥕🍚🪣🥬…） |
| 牌面立体感、投影、背景装饰 | ❌ 全无 |

**这不是 bug，是刻意的合规取舍。** 用 emoji 占位意味着没有提取任何原始美术资源，
代价是复刻版"结构全对、观感不对"。

> 一句话：**这套工具复刻的是关卡结构，不是画面。**
> 拿它当成品会失望，拿它当数据提取器正好。

### 能用来做什么

- 量出同类关卡的**密度参数**：38 张 / 12 类型 / 50% 可点 / 侧堆 10 层
- 学**叠放规则**：哪些牌压哪些牌、z 序怎么排
- 做自己的关卡时，照这个密度配比设计，不会过疏或过密
- 对比自己的关卡与竞品的难度曲线

### 不能用来做什么

- ❌ 当"复刻成品"演示（观感差距大）
- ❌ 作为"抄得像"的证明（本来就不该像）
- ❌ 把 emoji 换成原图标（那就越界了）

## 7. 演进路线

| 优先级 | 事项 | 价值 |
|---|---|---|
| 高 | 跨关卡累积模板库，统计每型样本数与命中率 | 第二关起人工介入趋近于 0 |
| 高 | 把 `pipeline.mjs` 包成 craft-anything 的工具（MCP/CLI） | agent 可在复刻流程里自动调用 |
| 中 | 用像素边缘判定遮挡关系，替代"可点/被压"二分 | 层级更准，复刻页手感一致 |
| 中 | 自动识别侧堆张数与内容（若堆内牌有错位可辨） | 批量时减少一个手工文件 |
| 低 | 从 `level.json` 直接生成 Vite 原型骨架 | 少一次搬运 |
